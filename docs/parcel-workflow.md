# Сценарій «власна ділянка / пошук території»

Статус: реалізація наступного етапу за запитом команди; завершення перевірок 2026-11-15.
Контрольний коміт перед зміною сценарію: `3c8d748`.
Повнота прогнозу та правил лишається окремою перевіркою:
[planning-data.md](planning-data.md), [data-readiness.md](data-readiness.md).

## Послідовність

1. **Мета.** «Обрати свою ділянку» (`own_land`) або «Знайти відповідні ділянки»
   (`find_land`). Великі окремі кнопки, без реєстрації.
2. **Територія.** Для власної ділянки — справжня карта з малюванням контуру
   точками або рамкою. На цьому етапі немає індексу чи кольорів придатності.
   Потрібні замкнений непорожній контур та повне входження в пілотний bbox Канзасу.
   Для пошуку — явний вибір пілотного регіону Канзасу; решта регіонів без аналізу.
3. **Культура.** Вибір однієї із семи культур або допомога з історичним
   порівнянням для власної ділянки. Підбір не обирає культуру замість користувача.
   Один шар карти завжди відповідає одній обраній культурі.
4. **Умови.** Масштаб у гектарах, доступність поливу, заданий користувачем
   сценарний обсяг води або «невідомо». Площа власного контуру визначається з
   геометрії; у пошуку вводиться бажаний масштаб господарства. Історичний сезон
   і його опорна дата відокремлені від цільового року планування.
   До аналізу видно недоступність підтвердженої дати сівби й норми поливу.
5. **Результат на карті.** Кольори для культури й обраних історичних умов,
   параметри території, чинники, економіка, прогноз, правила та прогалини.
   Власна ділянка зберігає контур; пошук відкриває пілотний регіон.
   Редагування попередніх кроків зберігає введення й не лишає старі кольори
   як результат нових налаштувань.

## Межі пошуку

Пошук показує дослідницьку придатність зон. Це не перелік вільних земель,
не кадастр, не перевірка власності й не пропозиція оренди. Бажана площа не
перетворює аналітичний полігон на господарське поле потрібного розміру.
Для точного добору полів за площею потрібні додаткові кадастрові/земельні дані,
яких зараз немає. Невідомі зони залишаються «Без даних».

## Допомога з вибором культури: контракт

Використовується наявний `/api/insights` для однієї опорної точки всередині контуру:
`lon`, `lat`, завершений історичний `year`, `crop=corn`,
`planting=YEAR-05-01`, `irrigation_mm=0`, `irrigation_known=false`, `years_back=1`.
`crop=corn` тут визначає тільки опорний календар запиту; відповідь містить
усі сім культур із їхніми власними календарями моделі й не змінює вибір користувача.
Попередній сценарій враховує природні опади, не підтверджує доступність зрошення.

Модуль `crop-options.js` нормалізує `crop_comparison`:

- `options[]`: `crop`, `score` (0–100 або `null`), `status`, `eligible`,
  `costPerHa` (USD/га), `pricePerTonne` (USD/т), окремі `economicYear`,
  `economicRegion`, `sourceLabel`, `localWarning`;
- `period`, `scopeLabel`, `limitations`, `sourceUrls`.

Сортуються лише справжні `score` після перевірки покриву та обов'язкових входів.
`potential_score` до land-cover gate не підміняє відсутню оцінку. Нулі та `null`
залишаються різними. Яра пшениця не просувається автоматично через застереження
локального посібника; ручний вибір для дослідницького сценарію залишається доступним.
Ціни й витрати — історичні регіональні ERS; поточний ринковий попит невідомий.

Точка обирається всередині простого контуру: середина найдовшого внутрішнього інтервалу на середній широті. Центр bbox може опинитись за межами увігнутої ділянки, тому його не використовуємо.

Індекс в опорній точці не є оцінкою всіх ґрунтів контуру. Порівняння не є
доведеною рекомендацією майбутньої культури або точного календаря робіт.

## Межі цього етапу

Нові джерела, автоматичний оптимізатор сівби/поливу та суцільний серверний
попередній розрахунок карт сюди не входять. Для кешованих карт потрібен окремий
версійований продукт з маскою відсутніх даних, фактичними масштабами входів,
атомарним оновленням та вимірюванням швидкодії. План — у [planning-data.md](planning-data.md).

## Перевірка 2026-11-15

- 93 Python тести та 33 JavaScript тести пройшли; синтаксис активного коду перевірено.
- У браузері перевірено обидва входи, малювання контуру, геометричну площу,
  збереження контуру при поверненні, окрему бажану площу пошуку, невалідний
  цільовий рік і незавершений числовий ввід із блокуванням навігації до результату.
- Реальне історичне порівняння культур повернуло оцінки та економічні дані з
  видимими обмеженнями. Невідомі дані й локальні застереження не підмінено порадою.
- Після випадкового відкату копіювання відновлено базові файли з Git і новий
  код із локального браузера; перевірено наявність усіх 657 зареєстрованих
  артефактів джерел. Це кількість файлів, а не підтвердження повного покриття регіону.
- Сервер залишено на `http://127.0.0.1:4173`; фоновий попередній розрахунок карт
  і агрономічна польова валідація не виконувалися в цьому етапі.
