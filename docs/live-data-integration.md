# GrowWhere 0.2 — реальна карта та дані

Стан на 2026-11-15: англомовний локальний застосунок із серверним API. Актуальні інструкції
запуску — у [README застосунку](../apps/web/prototype/README.md).
Початковий макет 0.1 зі штучними зонами більше не є активною сторінкою.
Поточний сценарій має два входи та п’ять кроків:
[власна ділянка / пошук території](parcel-workflow.md). На початковій карті
власної ділянки аналітичний шар не завантажується до вибору культури й умов.

## Реалізовано

- Реальна карта OpenStreetMap у Leaflet 1.9.4: перетягування, коліщатко, дотики,
  масштабування кнопками й клавіатурою; збережена атрибуція постачальників.
- Навігація й вибір контуру — область Північної Америки; фактичні готові оцінки
  обмежено Канзасом, bbox `[-102.1,36.9,-94.5,40.1]`. Інші території — No data.
- Активна карта читає готові версії з SQLite, без розрахунку в клієнтському запиті.
  [Контракт, підготовка та оновлення](prepared-maps.md). У пайплайні огляду — комірки 2°×2.5°, 1°×1.25° або 0.5°×0.625°;
  кожна комірка агрегує вибірку в **5 точках** (центр і 4 внутрішні чверті) з показником розкиду (`uncertainty`), а не бере одну випадкову центральну точку.
- Живий дослідницький адаптер підтримує справжні ґрунтові полігони SSURGO від zoom 12,
  до 400 за запит. В активному готовому шарі вони ще не підготовлені: збільшення
  карти зберігає рідну оглядову геометрію та не створює нової аналітичної точності.
- Культура, рік, опорна дата й кількість поливу вибирають підготовлений сценарій;
  відсутній сценарій показує No data. Застарілі відповіді не перемальовують
  новий запит. Прогалини не підміняються демонстраційними значеннями.
- Результати мають період, походження й дату отримання. Кожні 5 хвилин вкладка
  перечитує готові результати. Ручне оновлення карти не завантажує першоджерел.
  Для переобчислення потрібен окремий job; фонового планувальника поки немає.
  Прогноз, економіка та додатковий точковий аналіз мають окремі API й TTL.

Новий етап: актуальний NOAA NWS прогноз і K-State правила для вибраної точки
відокремлено від історичного індексу. [Контракт готовності](planning-data.md).
Дата сівби й норма поливу не рекомендуються за відсутніх критичних даних;
опорна дата сценарію не є рекомендацією. Автоматичні 250 мм прибрано.

## Реальні підключення

| Адаптер | Дані й роль |
| --- | --- |
| NASA POWER Daily | Температура, мінімум/максимум, опади, вологість повітря, вітер, радіація; FAO-56 ET₀ та ETc; `GWETTOP` (0–5 см) і `GWETROOT` (0–100 см) |
| NASA GIBS WMTS (карта) | Візуальні супутникові шари `MODIS_Terra_NDVI_8Day` (250–500 м) та `SMAP_L4_Analyzed_Root_Zone_Soil_Moisture` (~9 км) без API-ключів |
| USDA SDA / SSURGO | Справжні ґрунтові полігони, pH, AWC, пісок, глина, дренаж і схил; домінантний компонент, шар 0–30 см |
| USDA CDL / CroplandCROS | Покрив у точці вибірки за точний рік; невідомий — «Без даних», вода/забудова/ліс/болота/сніг — «Поза аналізом» |
| NOAA NWS hourly | Короткострокова погода для точки; не температура посівного шару й не вхід історичного індексу |
| USDA ERS | Регіональні річні витрати й історична ціна під час збирання; не поточний попит |

Реєстр походження: [datasets.json](../data/catalog/datasets.json). Завантаження
зберігаються незмінними в `data/raw/live/`, індекси кешу — у `data/processed/live-cache/`.
Кожна відповідь має URL/параметри запиту, час і SHA-256. Нові файли не змінюють
попередні сирі відповіді. Ключів доступу ці адаптери не потребують.

## Метод і обмеження

[Методика](live-methodology.md) описує сім чинників, ваги, FAO-56, граничні умови
та правила відсутності даних. Це дослідницький індекс первинного відбору;
його ваги й пороги ще не відкалібровано на врожаях Канзасу. Числові й інтеграційні
перевірки не є агрономічною валідацією.

Детальність ґрунтових полігонів не підвищує деталізації NASA: метеорологія
близько 0.5°×0.625°, радіація близько 1°. [CDL](landcover-live.md) перевіряє піксель
у точці, а не вирізає весь растр по кожному полігону. Це не кадастрові межі полів.
Пасовища допускаються лише до попередньої оцінки з видимим застереженням.

[Економіка](economics-live.md) не встановлює поточний регіональний попит:
відповідне поле явно «Без даних». Немає синтетичних цін або обіцянок прибутку.
Решта джерел із початкових 24 позицій показані як не підключені; не слід
заявляти, що всі місії вже інтегровані або механічно усереднювати дубльовані сигнали.

## Контракт API

- Активний аналітичний шар: `GET /api/map-products` і
  `GET /api/map-products/tiles` — [версійований контракт читання](prepared-maps.md).
- `GET /api/analysis?bbox=w,s,e,n&zoom=...&crop=wheat|soy|corn|sorghum|barley|oats|cotton&year=...&planting=YYYY-MM-DD&irrigation_mm=...&irrigation_known=true|false&refresh=0|1`
  — дослідницький живий API, який активна карта не викликає; повертає GeoJSON FeatureCollection з `soil`, `climate`, `landcover`, `result`
  (включно з `limiting_factor` і `water_balance`) та компактним `source_meta`; `meta` містить метод, просторовий масштаб, дати й помилки.
  Повторні запити кешуються на рівні пам’яті й диска (`SourceCache`), точкового та полігонального просторового кешу (`soil.py`, `landcover.py`) й у браузері (`analysisCache` за рівнем масштабу).
- `GET /api/insights?lon=...&lat=...&crop=...&year=...&planting=YYYY-MM-DD&irrigation_mm=...&irrigation_known=true|false&years_back=5&refresh=0|1` — порівняння всіх 7 культур і компромісів на точці (`crop_comparison`, `tradeoffs`), 5-річний кліматичний ризик NASA POWER (`climate_risk`), орієнтовні плани сівозмін (`rotation_advice`) та вологість ґрунту (`surface_wetness`, `root_zone_wetness`).
- `GET /api/economics?crop=...&year=...&refresh=0|1` — лише сумісні рік/регіон/одиниці або явні `null`.
- `GET /api/sources` — стан усіх початкових джерел і доданого ERS.
- `GET /api/planning-readiness?crop=...&lon=...&lat=...` — прогноз, часткові локальні правила, критичні прогалини; [детальний контракт](planning-data.md).
- `GET /api/health` — доступність локального сервера.
- `POST /api/report-pdf` — PDF одного поля або порівняння двох знімків,
  JSON до 2 MiB; локальна генерація без запитів до аналітичних джерел.
  [Контракт і формули](field-reports.md).

Стани результату: `good`, `conditional`, `poor`, `unknown`, `excluded`.
`unknown` означає брак обов'язкових даних; `excluded` — відомий покрив у точці,
для якого цей аналіз не застосовується. Тільки перші три мають числовий індекс.
Поточна версія підтримує сезон у межах одного календарного року.

## Подальший розвиток

Польова валідація й калібрування, повне растрове маскування покриву, точні межі
господарств, перевірені ринкові звіти, повне континентальне покриття й планувальник
підготовлених продуктів. Для онлайн-роботи
потрібне розгортання серверного API; публікація лише статичної папки `dist/`
не забезпечить отримання даних. Поточний локальний сервер не є production-хостингом.
