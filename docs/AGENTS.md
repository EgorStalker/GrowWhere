# Сфера: документація

Спочатку застосуй кореневі [AGENTS.md](../AGENTS.md) та [PROJECT.md](../PROJECT.md),
потім [rightversion-docs](../.agents/skills/rightversion-docs/SKILL.md).
Для пошуку документів використовуй [INDEX.md](INDEX.md).

- `PROJECT.md` містить стислий загальний контекст; не перетворюй його на повне ТЗ або журнал.
- Вимоги, дослідження, контракти й матеріали презентації створюй окремо, коли вони потрібні, та додавай до індексу.
- У [decisions.md](decisions.md) зберігай рішення зі статусом і причиною. Не називай робочу пропозицію погодженою вимогою.
- У `references/` зберігай надані або отримані першоджерела. Оригінали не редагуй; висновки пиши окремо.
- Для зовнішнього твердження вказуй джерело та дату перевірки. Збережений текст без URL не доводить актуальність сайту.
- Повний офіційний опис challenge ще не надано. Не дописуй із припущень критерії оцінювання, дедлайни або обов'язкові функції.
- Якщо потрібні характеристики чи доступність даних, підключи [сферу даних](../data/AGENTS.md); не дублюй каталог у документації.
- Ліцензії, цитування та застереження NASA переносити в публічні матеріали потрібно відповідно до перевірених умов конкретних джерел.
