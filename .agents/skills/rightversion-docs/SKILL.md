# Робота з документацією RightVersion

Якщо ще не прочитано, відкрий кореневі [AGENTS.md](../../../AGENTS.md),
[PROJECT.md](../../../PROJECT.md), [інструкції документації](../../../docs/AGENTS.md)
та [індекс](../../../docs/INDEX.md). Далі обери тільки потрібний документ.

- Визнач призначення матеріалу й читача: вимоги, обґрунтування, контракт, рішення чи презентація.
- Відділи слова команди та цитовані джерела від власної інтерпретації. Продуктовий напрям у `PROJECT.md` не замінює детального ТЗ; для MVP читай `docs/mvp.md`, де вимоги відділено від пропозицій.
- Для ресурсного твердження знайди конкретну позицію каталогу; повний англійський оригінал відкривай лише для перевірки формулювання.
- Актуальні умови хакатону та характеристики продуктів перевіряй за офіційними джерелами, коли завдання їх потребує. Запиши URL і дату, не підмінюй невідоме припущенням.
- Нова вимога або рішення має мати явний статус. Суттєві домовленості додавай у `docs/decisions.md`, а нові документи — у `docs/INDEX.md`.
- Перевір узгодженість зміненого матеріалу зі стислим контекстом; онови `PROJECT.md` лише якщо змінився спільний факт або етап проєкту.
