# Сфера: дані й аналітика

Спочатку застосуй кореневі [AGENTS.md](../AGENTS.md) та [PROJECT.md](../PROJECT.md),
потім [rightversion-data](../.agents/skills/rightversion-data/SKILL.md).

## Що читати

1. [README.md](README.md) — фактична наявність, шари зберігання та контракт метаданих.
2. Знайди потрібні рядки в [catalog/sources.csv](catalog/sources.csv) за `id`, сигналом або географією.
3. Відкрий метадані конкретних артефактів у [catalog/datasets.json](catalog/datasets.json).
4. Читай відповідний фрагмент [першоджерела](../docs/references/challenge-resources.en.txt) лише за потреби перевірити опис.

Для поточної реалізації спершу відкрий [контракт інтеграції](../docs/live-data-integration.md).
Формула — `pipelines/growwhere/analysis.py`, обґрунтування — [методика](../docs/live-methodology.md).
Адаптери: `sources.py`, `soil.py`, `landcover.py`, `economics.py`; вікно карти — `service.py`.
Ключі додаткових джерел зберігаються в `catalog/additional-sources.csv`.
Для зміни одного адаптера не потрібно читати сирі відповіді інших джерел.

## Наукові й технічні межі

- Перелік ресурсів не гарантує доступу, безкоштовної квоти або дозволу на повторну публікацію. Перед отриманням перевір офіційний продукт, версію, API, умови й цитування; запиши URL та дату перевірки.
- Географія демонстрації ще не обрана. Американські джерела не є автоматично придатними для України або будь-якого іншого регіону.
- Розрізняй місію, конкретний продукт і локальний артефакт. Частоти, роздільність і змінні залежать від продукту; узагальнення з наданого тексту не є технічною специфікацією.
- Перед суміщенням перевір CRS, просторову підтримку, період, часовий крок, одиниці, пропуски, QA-прапорці та метод агрегування. Перевибірка сітки не створює нової просторової інформації.
- Розрізняй спостереження, реаналіз, модельні оцінки та синтетичні приклади. Зокрема, OpenET не називай незалежною наземною істиною без окремої валідації.
- NDVI, температура поверхні та вологість є індикаторами; самі по собі не доводять причину стресу, врожайність або оптимальність сівозміни.
- Для прогнозів не допускай потрапляння майбутніх або просторово залежних даних у перевірочну вибірку. Описуй доступні перевірки й невизначеність без вигаданих метрик.
- Сирі артефакти зберігай незмінними; обробки роби відтворюваними з посиланням на вхідні набори. Секрети доступу зберігай поза репозиторієм.
- Погоджений вихідний формат для сайту опиши в окремому контракті в `docs/` і додай до індексу. Для роботи з UI підключи відповідні інструкції коду.
