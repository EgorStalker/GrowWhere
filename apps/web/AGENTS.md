# Сфера: сайт і код

Спочатку застосуй кореневі [AGENTS.md](../../AGENTS.md) та [PROJECT.md](../../PROJECT.md),
потім [rightversion-web](../../.agents/skills/rightversion-web/SKILL.md).

## Стан і межі

Це місце для коду застосунку, його API, конфігурації й перевірок.
Поточна версія — у [prototype/](prototype/README.md): HTML/CSS/JavaScript, локальний
Leaflet 1.9.4 і Python API. Із цієї папки `npm start` запускає локальний сервер;
`npm test` виконує перевірки реальної методики та адаптерів. Вихідні файли `dist/`
підтримуються як код і мають зберігатися в історії. Потрібен Python 3, доступний
командою `python` (або `GROWWHERE_PYTHON`), і доступ до інтернету.
Активна версія англійською; документація й спілкування з командою українською.
Активні модулі — `prototype/dist/js/live-*.js`; словник — `live-i18n.js`, частина
нових текстів ще в шаблонах `live-app.js`. Старі demo-модулі не є активним entrypoint.
Для інтеграцій читай [live-data-integration.md](../../docs/live-data-integration.md),
для наукових змін — методику й `data/pipelines/growwhere/analysis.py`.
Код обробки й отримання даних розміщуй у `data/pipelines/`, коли він знадобиться;
код обслуговування застосунку — тут. Карта читає готові версії SQLite через
`prepared-maps.js`; контракт та job — [prepared-maps.md](../../docs/prepared-maps.md).
Не повертай живий перерахунок у запити карти. Не створюй технологічний каркас лише через наявність цієї папки.

## Контекст за потребою

- Для вимог або UX відкрий [індекс документації](../../docs/INDEX.md), потім потрібний документ.
- Для візуальних змін прочитай [brand.md](../../docs/brand.md): продукт називається GrowWhere, команда — RightVersion; використовуй наданий логотип і схожу гаму.
- Для вже ухвалених технологічних рішень шукай відповідний запис у [decisions.md](../../docs/decisions.md).
- Для підключення даних прочитай [правила даних](../../data/AGENTS.md), метадані конкретного набору в `data/catalog/datasets.json` та його контракт. Повний перелік місій для звичайної UI-зміни не потрібен.

## Обмеження реалізації

- Відсутні дані, нулі та помилки завантаження мають різні стани.
- Орієнтуйся на недосвідченого користувача: великі елементи керування, одна зрозуміла основна дія, доступна довідка й вибір зі списку як альтернатива карті.
- Приклади показуй як демонстраційні; для реальних результатів відображай джерело, період, одиниці й суттєві обмеження.
- Не подавай крупномасштабні супутникові оцінки як точні вимірювання окремого поля.
- Формат запитів/відповідей і обмін із пайплайном зафіксуй у `docs/`, перш ніж дві частини почнуть залежати від нього.
- Після появи коду додай тут реальні команди запуску й перевірок, а в кореневому README — короткий старт.
- Виконай перевірки, доречні до зміни; не повідомляй про тести, які не запускалися.
